# 关于 IPv6

默认全关。这一页解释为什么要关到「网卡」这一层,以及怎么开回来。

## 五层

| 层 | 做什么 | 挡住什么 |
|---|---|---|
| 1 | DNS 只回 A 记录(`ipv4_only`) | 程序拿不到 AAAA,自然不会去连 v6 |
| 2 | 不分配 IPv6 的 fake-ip 段 | fake-ip 只走 v4 |
| 3 | 隧道里按目标协议族拒绝 | 硬编码 v6 地址的连接被拒 |
| 4 | TUN **照样声明** IPv6 地址,把 v6 流量接进隧道再丢掉 | 不接进来的话它会绕过隧道从物理网卡直接出网,等于泄漏 |
| 5 | 连接期间**停用各网卡的 IPv6 协议** | 地址根本不存在,程序读不到 |

局域网的 `fc00::/7`、`fe80::/10`、`ff00::/8` 仍留在隧道外,不影响本地设备互访。

## 第五层为什么必要

前四层挡的都是「IPv6 **数据包**出网」,挡不住「**读取本机网卡配置**」。

运营商用路由器通告发下来的公网 IPv6 地址,明明白白配在物理网卡上。任何原生程序(**不是网页** —— 浏览器沙箱不给读)枚举一遍网卡就能读走,再经隧道报给自己的服务器:

> 数据包一点没漏,信息漏了。而那个前缀对应到具体一条宽带线路,定位价值不比公网 IPv4 差。

地址本身不存在,才是真的读不到。

## 各平台怎么关的

| 平台 | 做法 |
|---|---|
| Windows | 停用 `ms_tcpip6` 绑定(等同于适配器属性里取消勾选「Internet 协议版本 6」) |
| Linux | `sysctl net.ipv6.conf.<网卡>.disable_ipv6=1` |
| macOS | `networksetup -setv6off` 按网络服务逐个关 |
| Android | **做不到** —— 应用没有权限改物理网卡配置,只有第 1–4 层 |

隧道自己那张网卡**一律不动** —— 它要靠 v6 地址把 v6 接进来再拒绝,关了反而少一层。

Windows 上的隐藏接口(Teredo、6to4、IP-HTTPS、Wi-Fi Direct 虚拟网卡)程序也一并停用、断开时还原。下面几种情况得自己动手 —— 上面挂着公网 v6 时,全局模式 +「防流量逃逸」下连接会被拒绝,规则 / 普通全局下照常连、首页挂一条警告(拒绝的话连 IPv4 也全部直连,反而更糟),都会点名是哪张:

- **电脑直接 PPPoE 拨号**且运营商下发了 IPv6(拨号连接不是网卡,程序改不到):到「网络连接」里那条拨号连接的属性 → 网络,取消勾选「Internet 协议版本 6」,重新拨号。
- **Teredo** 停用后地址还在(`2001:0:` 开头,地址里编着你的公网 IPv4):管理员命令 `netsh interface teredo set state disabled`。
- **6to4**(`2002:` 开头)/ **IP-HTTPS** 同样停不掉时:`netsh interface 6to4 set state disabled`、`netsh interface httpstunnel set interface client state=disabled`。

这几条关掉之后程序不会替你开回来,要恢复就把对应命令里的 `disabled` 换成 `default`。

## 安全绳

- 动手前把**每张网卡当时的状态**落盘,断开时按状态还原。
- 守护进程启动时**对账一次**:上次不是连着关的机(或者你已经关掉这一项)就还原回去;上次是连着关的机就接着关着 —— 网卡 IPv6 和「防流量逃逸」的闸一样是持久的,不然关机到下次连上之间那段时间地址又露出来了。Linux 上停用写的是运行期设置、不过重启,所以关着时另写一份 `/etc/sysctl.d/90-godusevpn-ipv6.conf`:systemd 开机时、以及每张网卡出现时(开机晚出现的、被改名的也算)都按它关掉,断开、卸载时删掉。但 systemd-networkd / NetworkManager 配置网卡时还会按自己的配置改回开(真机重启实测),所以开机闸同时挡住路由器通告(地址就是靠它发下来的),守护进程起来重新停用后再放开;连着的时候每 5 秒也看一眼有没有被改回开。OpenWrt 由开机闸的脚本在联网前按备份关一遍,之后才出现的网卡(拨号口)要等守护进程起来;梅林做不到。
- 连接状态读不出来时(比如状态文件被删),不当成你断开过:设置是「全局 + 防流量逃逸 + 关 IPv6」、或闸还在、或闸在不在查不到,都接着关着;只有设置不要求这样、闸也确实不在,才还原回去。要拿回 IPv6,点一次断开或用「恢复网络」。
- 本来就是关闭状态的网卡记下来但不动,还原时也不去开它(那是你自己关的)。
- 还原时网卡不在(连着时拔掉了 USB 网卡 / 手机 USB 共享):Windows 把「IPv6 已停用」记在那张网卡上,插回来仍是关的。它会被记进待还原清单,并在首页提示;再插上后下次断开连接(或「恢复网络」、卸载)时自动开回,中间又连上的话也按「本来是开着的」记账,不会被当成你自己关的。
- 记的是「动手前每张网卡各是什么状态」,不是「我关了哪几张」:实测发现关掉某张网卡会连带把 Hyper-V 的虚拟网卡也变成关闭,只记自己动过的那几张,还原时会漏。
- **连接期间新冒出来的网卡也管**:插 USB 网卡、手机 USB 网络共享、开热点、起虚拟机或 WSL,都会多出一张没被处理过的网卡,上面的公网 v6 地址照样能被读走。守护进程每 5 秒用系统接口看一眼(不起子进程,很便宜),真发现了才去停用那一张,并把它动手前的状态**补记**进备份,断开时照样还原得回来。

## 想开回来

设置 → 隐私 → 关掉「连接时停用网卡 IPv6」。想让 v6 流量真的能出去,还要把设置里的 IPv6 开关打开(那会同时放开上面 1–3 层)。

网关模式下这一项**照样生效**,那正是希望整个局域网都没有 v6 出口的场景;要保留局域网 IPv6 就把它关掉。

## 只能走 IPv6 的节点

「允许 IPv6」关着时,关着 IPv6 就是不走 IPv6 —— 连节点这一跳也一样,**不分平台**(Android、桌面不开 TUN、关掉「连接时停用网卡 IPv6」时也一样:那些情况下网络有 IPv6 的话本来拨得通,可那就是在走 IPv6)。所以这两种节点这一轮不用,节点列表里标成「IPv6 节点」:

- **地址直接写成 IPv6 的节点**(面板给线路选了 IPv6 时就是这样)。内核里这种节点改经一个拒绝出站,选了它也不会从本机拨出一个 IPv6 包。
- **域名只有 IPv6 地址的节点**:关着 IPv6 时节点域名只解析 IPv4(第 1 层),解析不出地址,本来就连不上。这是连接时解析节点域名顺带查出来的:本地 DNS 是 DoH 地址时,答「没有 A 记录」的再问一次 A 确认、再问一次 AAAA;本地 DNS 是 system 时,只解析出 IPv6 地址的再单问一次 IPv4 确认 —— 上游偶发一次空答复、A 查询超时都不会把双栈的节点判成这种。只用来分类,不拿它去连。全局模式 + 防流量逃逸下,本地 DNS 是 system 或域名形式的 DoH 时不做这次解析(那会在隧道外发明文查询),也就认不出来,连上后照样连不通,只是不会提前标出来。

它们不进自动选择,也不进线路自动;节点列表测速也不测它们(直接记「不通」,测它就是在走 IPv6)。选它照样能选上,但连不通,首页写明是哪个节点、去哪儿改;选的是线路而这条线路的服务器全是这种、或者自动选择而订阅里的节点全是这种,也一样写明。自救临时借了别的节点时,提示里会说明现在用的是哪台。

带中转的节点(sing-box 订阅里的 `detour`)按链的第一跳算:本机只连第一跳,后面那一跳由中转服务器去连、去解析 —— 中转是 IPv4 的,落地写成 IPv6 也照样能用;第一跳要走 IPv6 的,整条链都不用。节点列表测速也一样:带中转的节点经中转真连一次,不从本机直接连落地。

订阅里节点自带的解析策略(sing-box 已废弃的 `domain_strategy`,有的订阅转换工具会把 Clash 的 `ip-version` 转成它)一概不用:它会盖过客户端给节点域名定的「只解析 IPv4」,写了 `prefer_ipv6` 之类的节点照样经 IPv6 去连。节点域名怎么解析由客户端统一定。

以前的版本在 Android、桌面不开 TUN、关掉「连接时停用网卡 IPv6」时,会照样经 IPv6 去连地址写成 IPv6 的节点;现在「允许 IPv6」关着就不连。升级后这种节点(比如面板因为服务器的 IPv4 被墙、给线路选了 IPv6)连不上的话,打开「允许 IPv6」就能用。

不会为了连它们去打开网卡的 IPv6,也不放宽节点域名的解析。要用这种节点就到设置 → 隐私打开「允许 IPv6」(打开之后连接时也不再停用网卡的 IPv6),或者换别的节点。

## 程序自己直连发出去的请求

不经代理、由服务或界面自己发出去的请求 —— 没连接时拉订阅、点「检查更新」、下载安装包、补规则集、隧道起来之前解析节点域名的 DoH —— 在「允许 IPv6」关着时同样只走 IPv4:域名只解析 A 记录,写成 IPv6 的地址在拨号这一步就被拒,一个包都不发。

「本地 DNS」填的是 IPv6 地址而「允许 IPv6」关着时,连它就是在本机走 IPv6:这时改用按地址连的公共 DoH `223.5.5.5`(和防流量逃逸下替换 system 的是同一台);打开 IPv6 后照用填的地址。

交给系统配的 DNS 服务器解析(「本地 DNS」设成 system、没开防流量逃逸,以及没连接时拉订阅、检查更新)时:Linux、Android 上程序自己去问,配成 IPv6 地址的 DNS 服务器跳过、只问 IPv4 的;Windows、macOS 上是系统的解析服务去问,那一步程序管不到 —— 系统配了 IPv6 的 DNS 服务器时,查询本身可能经 IPv6 发出(查回来的 IPv6 地址照样不用)。不想这样就打开「连接时停用网卡 IPv6」(默认开着)。

## 怎么验

连上之后:

- 打开 <https://test-ipv6.com/>,IPv6 那几项应该全是失败 / 不支持。
- 打开 <https://bash.ws/dnsleak/test/>,应该只看到走代理出去的解析器。
- Windows 上 `ipconfig` 看物理网卡,不应该再有公网 v6 地址(`2xxx:` / `2409:` 开头那种)。
- 想验第五层对**新网卡**也生效:连着的时候插一张 USB 网卡或打开手机热点,半分钟内再看 `ipconfig`,那张新网卡上也不该有公网 v6 地址;服务日志里会有一行「发现网卡上又有公网 IPv6 地址」。
- 断开之后再 `ipconfig`,地址应该回来。
