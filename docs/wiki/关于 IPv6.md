# 关于 IPv6

默认全关。这一页解释为什么要关到「网卡」这一层,以及怎么开回来。

## 五层

| 层 | 做什么 | 挡住什么 |
|---|---|---|
| 1 | DNS 只回 A 记录(`ipv4_only`) | 程序拿不到 AAAA,自然不会去连 v6 |
| 2 | 不分配 IPv6 的 fake-ip 段 | fake-ip 只走 v4 |
| 3 | 隧道里按目标协议族拒绝 | 硬编码 v6 地址的连接被拒 |
| 4 | TUN **照样声明** IPv6 地址,把 v6 流量接进隧道再丢掉 | 不接进来的话它会绕过隧道从物理网卡直接出网,等于泄漏 |
| 5 | 连接期间**停用各网卡的 IPv6 协议** | 地址根本不存在,程序读不到 |

局域网的 `fc00::/7`、`fe80::/10`、`ff00::/8` 仍留在隧道外,不影响本地设备互访。

## 第五层为什么必要

前四层挡的都是「IPv6 **数据包**出网」,挡不住「**读取本机网卡配置**」。

运营商用路由器通告发下来的公网 IPv6 地址,明明白白配在物理网卡上。任何原生程序(**不是网页** —— 浏览器沙箱不给读)枚举一遍网卡就能读走,再经隧道报给自己的服务器:

> 数据包一点没漏,信息漏了。而那个前缀对应到具体一条宽带线路,定位价值不比公网 IPv4 差。

地址本身不存在,才是真的读不到。

## 各平台怎么关的

| 平台 | 做法 |
|---|---|
| Windows | 停用 `ms_tcpip6` 绑定(等同于适配器属性里取消勾选「Internet 协议版本 6」) |
| Linux | `sysctl net.ipv6.conf.<网卡>.disable_ipv6=1` |
| macOS | `networksetup -setv6off` 按网络服务逐个关 |
| Android | **做不到** —— 应用没有权限改物理网卡配置,只有第 1–4 层 |

隧道自己那张网卡**一律不动** —— 它要靠 v6 地址把 v6 接进来再拒绝,关了反而少一层。

## 安全绳

- 动手前把**每张网卡当时的状态**落盘,断开时按状态还原。
- 守护进程启动时也**无条件还原一次**:上次崩溃退出不会把你的 IPv6 永久关掉。
- 本来就是关闭状态的网卡记下来但不动,还原时也不去开它(那是你自己关的)。
- 记的是「动手前每张网卡各是什么状态」,不是「我关了哪几张」:实测发现关掉某张网卡会连带把 Hyper-V 的虚拟网卡也变成关闭,只记自己动过的那几张,还原时会漏。
- **连接期间新冒出来的网卡也管**:插 USB 网卡、手机 USB 网络共享、开热点、起虚拟机或 WSL,都会多出一张没被处理过的网卡,上面的公网 v6 地址照样能被读走。守护进程每 30 秒用系统接口看一眼(不起子进程,很便宜),真发现了才去停用那一张,并把它动手前的状态**补记**进备份,断开时照样还原得回来。

## 想开回来

设置 → 连接 → 关掉「连接时停用网卡 IPv6」。想让 v6 流量真的能出去,还要把设置里的 IPv6 开关打开(那会同时放开上面 1–3 层)。

网关模式下这一项**照样生效**,那正是希望整个局域网都没有 v6 出口的场景;要保留局域网 IPv6 就把它关掉。

## 怎么验

连上之后:

- 打开 <https://test-ipv6.com/>,IPv6 那几项应该全是失败 / 不支持。
- 打开 <https://bash.ws/dnsleak/test/>,应该只看到走代理出去的解析器。
- Windows 上 `ipconfig` 看物理网卡,不应该再有公网 v6 地址(`2xxx:` / `2409:` 开头那种)。
- 想验第五层对**新网卡**也生效:连着的时候插一张 USB 网卡或打开手机热点,半分钟内再看 `ipconfig`,那张新网卡上也不该有公网 v6 地址;服务日志里会有一行「发现网卡上又有公网 IPv6 地址」。
- 断开之后再 `ipconfig`,地址应该回来。
