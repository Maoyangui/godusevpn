# 排障

先从这三条开始:

```bash
godusevpn-cli status          # 它自己认为现在在哪一步
godusevpn-cli logs 200 core   # 内核说了什么
godusevpn-cli diag            # 要发给别人看就导这个(订阅地址已打码)
```

界面上对应:侧边菜单 → 日志,切到「内核」;右上角「导出诊断包」。

## 界面显示「服务未运行」

界面和守护进程是两个进程,这行字的意思是**连不上守护进程**。

1. 关于页点「修复服务」。
2. Windows 上还可以 `godusevpn-svc install` 重装一次服务。
3. macOS 的界面是**用户身份**跑的,要靠 root 守护进程开出来的套接字;重装服务能一并修好那个套接字的权限。
4. Linux 上 `godusevpn status` 看服务在不在,`godusevpn start` 拉起来。

## 连上了,但打不开网页

按这个顺序查:

1. **节点是不是已经不通了**。打开节点列表点「重新测速」,看哪些还活着,换一个。
2. **DNS**。日志里搜 `dns`;fake-ip 开着的话正常应该看到 `198.18.x.x` 这样的地址。
3. **模式**。是不是不小心切到了「直连」或者某条规则把目标拒了(连接页能看到命中哪条规则)。
4. **严格路由**。个别虚拟网卡 / 安全软件会跟它打架,可以先关掉试试(设置 → 连接)。

## 一连上远程机器就断

Linux 上不会:连上后会给每个物理网卡地址加一条「回包走主表」的策略路由,本机对外服务的回包不进 TUN。

要是仍然断了,说明你的服务监听在一个没被识别到的地址上。先 `godusevpn-cli disconnect` 断开(SSH 会恢复),把地址贴到 Issue 里。

## 订阅刷新失败

刷新会自动回退:**经当前节点 → 自动选择组 → 直连**。三条都失败基本是链接本身的问题:

- 到订阅管理里核对地址有没有抄错。
- 账号可能已停用 / 用完 / 到期 —— 这几种情况面板一般会在错误里说明。
- 面板端口被本机规则判成了代理:节点服务器与面板的地址会自动加直连规则,如果你自己写了规则组把它盖住了,检查一下。

## 节点全是「不通」

- 内核没跑的时候,列表显示的是**本机到节点服务器的直连延迟**;连上之后才是按出站实测。这两者不一样。
- 全是不通又连不上,多半是订阅本身的节点都挂了,或者本地网络出不去。

## Windows:装完 TUN 没起来

- 看 `godusevpn-cli logs 200 core`,搜 `tun`。
- 常见冲突:别的 VPN / 加速器占着 WinTun,或者安全软件拦了网卡创建。
- 协议栈换成 `gvisor` 再试(设置 → 连接 → TUN 协议栈)。

## macOS:网页打不开、DNS 不对

连接时会接管系统 DNS,断开还原。如果上次是崩溃退出的,守护进程下次启动会无条件还原一次。
手动还原:系统设置 → 网络 → 对应服务 → DNS,清空成自动。

## Android:连上没网

- 系统里是不是还有另一个「始终开启的 VPN」占着。
- 省电优化可能把后台服务杀了,把应用加进白名单。

## IPv6 相关

见 [[关于 IPv6]] 最后一节的验证方法。断开之后网卡的 v6 地址应该会回来;没回来的话重启一次守护进程,它会无条件还原。

## 还是不行

带上诊断包和现象开 [Issue](https://github.com/Maoyangui/godusevpn/issues)。诊断包里有:设置(订阅地址打码)、最近的服务与内核日志、渲染出来的 `config.json`、系统与网卡信息。
