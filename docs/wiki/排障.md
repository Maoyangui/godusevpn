# 排障

先从这三条开始:

```bash
godusevpn-cli status          # 它自己认为现在在哪一步
godusevpn-cli logs 200 core   # 内核说了什么
godusevpn-cli diag            # 要发给别人看就导这个(订阅地址已打码)
```

界面上对应:侧边菜单 → 日志,切到「内核」;右上角「导出诊断包」。

## 界面显示「服务未运行」

界面和守护进程是两个进程,这行字的意思是**连不上守护进程**。

1. 关于页点「修复服务」。
2. Windows 上还可以 `godusevpn-svc install` 重装一次服务。
3. macOS 的界面是**用户身份**跑的,要靠 root 守护进程开出来的套接字;重装服务能一并修好那个套接字的权限。
4. Linux 上 `godusevpn status` 看服务在不在,`godusevpn start` 拉起来。

## 连上了,但打不开网页

按这个顺序查:

1. **节点是不是已经不通了**。打开节点列表点「重新测速」,看哪些还活着,换一个。
2. **DNS**。日志里搜 `dns`;fake-ip 开着的话正常应该看到 `198.18.x.x` 这样的地址。
3. **模式**。是不是不小心切到了「直连」或者某条规则把目标拒了(连接页能看到命中哪条规则)。
4. **严格路由**。个别虚拟网卡 / 安全软件会跟它打架,可以先关掉试试(设置 → 连接)。
5. **隧道会话坏了**。hysteria2 / TUIC 是一条长会话,换网络、睡眠唤醒之后它可能"活着却不投递":每个请求都卡到超时,而全局禁直连不许绕过去,表现就是整机断网、别的设备同一节点却正常。守护进程会自己判废重建(40 秒内 5 次失败就拆掉重连,并立刻做一次健康检查),从坏掉到重新握好一般是一两分钟的事;`godusevpn status` 里「隧道:判废 N 次,重建 N 次」那一行在涨就是它在修。还不行就换节点。

## 一连上远程机器就断

Linux 上不会:连上后会给每个物理网卡地址加一条「回包走主表」的策略路由,本机对外服务的回包不进 TUN。

要是仍然断了,说明你的服务监听在一个没被识别到的地址上。先 `godusevpn-cli disconnect` 断开(SSH 会恢复),把地址贴到 Issue 里。

## 订阅刷新失败

刷新会自动回退:**经当前节点 → 自动选择组 → 直连**。三条都失败基本是链接本身的问题:

- 到订阅管理里核对地址有没有抄错。
- 账号可能已停用 / 用完 / 到期 —— 这几种情况面板一般会在错误里说明。
- 面板端口被本机规则判成了代理:节点服务器与面板的地址会自动加直连规则,如果你自己写了规则组把它盖住了,检查一下。

## 节点全是「不通」

- 内核没跑的时候,列表显示的是**本机到节点服务器的直连延迟**;连上之后才是按出站实测。这两者不一样。
- 全是不通又连不上,多半是订阅本身的节点都挂了,或者本地网络出不去。
- 全局禁直连开着、隧道还没起来时**不做直连测速**(测速包不该去撞闸),「重新测速」会提示先等隧道;那时候的「不通」是没测,不是节点挂了。

## Windows:装完 TUN 没起来

- 看 `godusevpn-cli logs 200 core`,搜 `tun`。
- 常见冲突:别的 VPN / 加速器占着 WinTun,或者安全软件拦了网卡创建。
- 协议栈换成 `gvisor` 再试(设置 → 连接 → TUN 协议栈)。

## macOS:网页打不开、DNS 不对

连接时会接管系统 DNS,断开还原。如果上次是崩溃退出的,守护进程下次启动会还原一次;只有上次是在严格全局模式下连着的才先保留接管(等闸和隧道重建,不让解析先走物理网卡),这时点「断开」或用「恢复网络」都会还原。
手动还原:系统设置 → 网络 → 对应服务 → DNS,清空成自动。

## Android / 电视:打开是白的

界面是网页,装在系统 WebView 里。老设备(尤其国行电视盒子)的 WebView 版本很旧,页面里有它不认的写法就会
整份脚本解析失败,只剩一个空壳 —— 看上去就是一片白。

现在页面自带兜底:出错时会把原因和设备的 UserAgent 直接显示在屏幕上,**拍下那一屏**发过来即可。
要是连兜底都没出来,说明连它也被拒了,那就走诊断包:壳会把 WebView 的版本号和页面报的错写进 logcat
(标签 `godusevpn`),「日志 → 导出诊断包」带得出来。

顺带一提:连接本身是在后台服务里跑的,界面白屏不代表没连上 —— 通知栏还在就说明隧道是通的。

## Android / 电视:一直「出错,自动重试中」

界面上那行小字现在会把内核的原话接在后面,先看它属于哪一类:

| 显示 | 多半是什么 | 怎么办 |
|---|---|---|
| 规则集读不出来 | `rulesets/` 里的 `.srs` 坏了 | 程序会自己重铺内置的那几份并重试;还不行就把 `rulesets/` 里你自己放的文件挪走(Windows 上要管理员权限才进得去) |
| 端口被占用 | 混合端口被别的代理软件占着 | 设置里换一个端口,或退掉那个程序。Clash API 端口被占时会自动换一个空闲的(服务日志里写着换成了哪个),不会因此连不上;Android / 电视开着 TUN 时不开混合端口,也撞不上 |
| TUN 网卡创建失败 | 系统 VPN 授权被撤、被另一个 VPN 应用抢走 | 到系统设置 → 网络 → VPN 里重新允许本应用,或关掉另一个 VPN |
| 内核启动失败 | 上面几类都不是 | 「日志」页里有内核的完整报错,拍一张发过来 |

电视上「日志」在左侧菜单里,遥控器选中日志框之后可以用上下键翻页。

> 早期版本(0.6.22 及以前)在这里只显示「内核启动失败」五个字,没有下文。
> 那时最常见的原因是**规则集要在内核启动时从 GitHub 现下,下不到就整个起不来** ——
> 一台全新设备只要第一次没下动,就会永远连不上。现在常用规则集随安装包内置,这条路已经不存在。

## Android:连上没网

- 系统里是不是还有另一个「始终开启的 VPN」占着。
- 省电优化可能把后台服务杀了,把应用加进白名单。

## Android / 电视:点连接没反应,或者应用直接退出

系统的 VPN 授权对话框由 `com.android.vpndialogs` 提供,少数不走 Google 认证的电视 / 盒子固件把它裁掉了。
现在遇到这种情况会提示「这台设备的系统里没有 VPN 授权界面」,可以到系统设置 → 网络 → VPN 里手动允许本应用。
按遥控器返回键取消掉授权框时也会提示一句,再点一次连接会重新询问。

## 电视:菜单最后几项(关于 / 导出诊断包 / 退出)看不到

老版本在 960×540 这类矮视口上会把菜单挤出屏幕且滚不到。现在菜单能滚,矮屏幕上也会自动收紧间距。
还是看不全的话,遥控器在菜单里一直按「下」就能滚下去。

## IPv6 相关

见 [[关于 IPv6]] 最后一节的验证方法。断开之后网卡的 v6 地址应该会回来;没回来的话重启一次守护进程,它会在启动时对账 —— 只要上次不是连着关的机就会还原回去。再不行就用开始菜单里的「恢复网络」。

## 全局模式下所有网站都打不开

大概率是「全局禁直连」在起作用:节点不通、或者内核还没起来,流量被闸拦住了,不会漏到直连——这正是它该做的。点了断开还是没网、状态里标着「撤闸失败」:那是闸没撤成(BFE 停了、权限不够之类),原因就在后面,按下面的四条路解除。看首页状态下面那颗小盾:有盾说明闸开着;换个通的节点,或者点断开。真要临时绕过,设置 → 隐私把「全局禁直连」关掉。

闸是**持久的**:服务被强杀、崩溃、升级都还在,重启后守护进程一起来就重新装上(Windows 连开机那几秒也堵着,macOS / Linux 开机到守护进程起来之间没有闸)——这是故意的,不然那几秒就漏了。所以服务起不来的时候机器会一直断网,要你来解除,四条路都不需要服务活着。服务要是活着,它们都会先把「全局禁直连」开关关掉(不然服务一重连又把闸装回来),要再用去设置 → 隐私打开:

1. 托盘菜单「恢复网络(解除禁直连闸)」;
2. 开始菜单「佛跳墙 → 恢复网络」(弹 UAC,做完弹个框告诉你结果);
3. 命令行:Windows `"C:\Program Files\godusevpn\godusevpn-svc.exe" guard clear`(弹 UAC),macOS / Linux `sudo godusevpn guard clear`;`guard status` 看闸开没开;
4. 卸载程序会先撤闸。

回退到旧版前先在本版里点「断开」(闸会连转发层一起撤掉)再装旧版:本版在转发层多了一组过滤器,0.6.24 及更早版本的撤闸 / 卸载不认识这一层,连着的时候直接手工换回旧文件会把它们留在系统里(热点 / 网络共享一直断),得重装本版再撤。0.7.4 起 Windows 的闸挂在新一代的提供者 / 子层下(从 0.6.25-m29 ~ 0.7.1 升上来时原地换掉绑了服务名的旧提供者,不必先断开),所以回退到 0.7.3 及更早版本同样要先「断开」——旧版的撤闸 / 卸载不认识新一代的对象。没先断开就装了旧版的表现是:断开后仍上不了网,而旧版的 `guard status`、「恢复网络」、卸载都说闸没开(它们看不见新一代的过滤器)——重新装回 0.7.4 或更新的版本,点「断开」或「恢复网络」(或跑它的 `guard clear`)就清掉了,之后再回退。

用 0.7.4 的安装包升级时如果中途失败(停不掉旧服务、安装被关机或被杀),机器上留下的旧版同样看不见新一代的闸,表现和上面一样:断开后没网,旧版的「恢复网络」说闸没开。**别卸载旧版**。旧版照样能连上隧道(新一代的闸放行它),先用旧版重新连上,再下载装上 0.7.5 或更新的版本,然后点「断开」即可。0.7.5 起安装包不再预装闸,不会再出现这种情况。

从 0.6.10-m12 ~ 0.6.12-m14 这三个预发布版**直接**升级时,旧版一停服务闸就没了(m12 / m13 的闸是动态的,m14 停服务时自己撤掉),到新版服务起来重新开闸之间有几秒到几十秒是直连。从这几版升级前,先点「断开」。0.6.13-m15 及以后的版本升级时闸通常一直在;0.7.4 及以前停服务时如果正好在重连或自检,有极小概率撤闸,0.7.5 起已堵上。

### 怎么确认重启后闸一直在(Windows)

以管理员身份跑 `"C:\Program Files\godusevpn\godusevpn-svc.exe" guard status`:第二行是"其中被系统标为停用(不拦任何包)的 N 条"。**N 大于 0**,或者后面多出一句"提供者带着系统的「开机时已停用」标志",或者服务日志(`C:\ProgramData\godusevpn\logs\service.log`)里开机后出现"本次开机时防火墙引擎停用过闸的规则",都说明开机那一段闸可能没生效,请把日志反馈给开发者。N 是 0、也没有那两句,就是正常的。

别手动删程序目录——规则在系统里,程序没了就没人删得掉;Windows 重装一遍再卸载即可,macOS / Linux 用 `sudo pfctl -a com.apple/godusevpn -F all` / `sudo nft delete table inet godusevpn_guard`。

## 检查更新提示「校验失败」或「没有发布校验和文件」

更新器是以管理员身份静默安装的,所以**拿不到校验和就不装** —— 不是跳过校验照装。
出现这两句说明下载到的安装包对不上官方发布的 SHA256,或者干脆没取到校验和文件(网络被劫持、
镜像站不完整都可能)。换个网络环境再试;一直不行就去 [Releases](https://github.com/Maoyangui/godusevpn/releases)
手动下载,自己对一下同目录 `SHA256SUMS` 里的值。

## 还是不行

带上诊断包和现象开 [Issue](https://github.com/Maoyangui/godusevpn/issues)。诊断包里有:设置(订阅地址打码)、最近的服务与内核日志、渲染出来的 `config.json`、系统与网卡信息。
